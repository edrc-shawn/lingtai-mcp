# 页面模板

#模板 #规范

> 本文档是 AI 新建丹房页面的格式规范参照。任何 AI 客户端（WB/Reasonix/QoderWork/MimoCode）建页时均以此为准。

## 格式强制要求

### frontmatter（YAML）

```yaml
---
标题: 页面标题
创建日期: YYYY-MM-DD
更新日期: YYYY-MM-DD
品级: 中品       # 上品/中品/下品
标签: [标签1, 标签2, 标签3]   # YAML 数组格式，用方括号逗号分隔
---
```

**注意**：
- 字段名用中文：`标题` 不是 `title`，`创建日期` 不是 `date`，`品级` 不是 `level`，`标签` 不是 `tags`
- `品级` 初始填 `中品`，不填空字符串
- `标签` 用 YAML 数组 `[a, b, c]`，不用 `- a\n- b` 格式

### 正文头部

```markdown
# 页面标题

#标签1 #标签2 #标签3

> 可选引述（摘要/来源说明）
```

**行内标签必须紧跟在 `# 标题` 之后**，作为第二行。

**为什么 frontmatter 和行内标签都要有？** 两个消费者各认一套：

| 位置 | 消费者 | 用途 |
|------|--------|------|
| frontmatter `标签:` | 灵台索引/检索 | 全文搜索、分类、图扩散 |
| 正文 `#标签` | Obsidian 知识图谱 | 可视化节点连接 |

**两者必须完全一致**。加标签时两套同步增删，拆不开。

### 标签规则

#### 主标签（首标签四选一）

第一个标签决定页面类型，必须从以下四项中选：

| 主标签 | 含义 | 典型内容 |
|--------|------|----------|
| `#概念` | 定义、原理、框架、模型 | 含人量、类AI人、O与π、判断力 |
| `#方法` | 操作步骤、技巧、SOP、流程 | 选题技巧、写作框架、冷启动策略 |
| `#痛点` | 问题诊断、困境分析、卡点 | AI味儿怎么去不掉、减肥平台期为什么难过 |
| `#工具` | 软件/平台/产品使用参考 | Obsidian Dataview 说明、灵台架构分析 |

#### 子标签规则

首标签之后自由添加 3-5 个子标签，必须满足：

- **具体可检索**：✅ `#嘟囔测试`  ❌ `#心理学`（太宽泛，搜出来几百条没意义）
- **描述内容方向，不放实体名**：✅ `#收敛工具`  ❌ `#灵台`（灵台是实体，不放标签里）
- **有图走价值**：每个子标签至少能在 Obsidian 图谱里连上 2-3 个其他页面——孤岛标签没有存在的意义

#### 总量：5-6 个

```markdown
#概念 #AI #含人量 #虚壳 #判断力
#方法 #自媒体 #内容创作 #行业分析 #IP
```

> 标签体系基于 `原料/灵台 标签体系（v3）.md`，根据实际使用数据简化为四主标签（砍掉了零使用的 `#案例` 和 `#灵感`）。

### 文件名约束

**文件名禁止使用引号**（弯引号 `""`、直引号 `""`）。改用直角引号 `「」` 或直接去掉。建新文件前自动检查，发现引号立即修正。

### wikilink 精度三阶

链接其他页面时按精度选择格式：

| 精度 | 格式 | 用途 |
|------|------|------|
| 整页引用 | `[[整页]]` | 引用整页主题 |
| 锚点引用 | `[[所在页#具体小节\|显示文字]]` | 引用具体论点 |
| 块引用 | `[[原料/xxx^块标记]]` | 指向原料某一段落 |

**禁止**：正文中裸写长 wikilink 让句子读不通——必须用 `|` 改显示文字。

### 链接目标规范（硬规则）

- **链接目标必须是文件名 slug**（不含 `.md`），不要用 frontmatter 的 `标题` 字段做链接目标。
- 需要美化显示文字时，用 `|` 分隔：`[[文件名|显示文字]]`。Obsidian 永远认文件名，不依赖别名缓存，最稳。
- **不使用 `aliases` 字段**：Obsidian 只按文件名或标准 `aliases` 解析 `[[wikilink]]`，自定义 `标题` 字段 Obsidian 不认；靠 `aliases` 通链依赖 Obsidian 重新读索引，外部改文件时常不刷新，不稳定。统一走文件名定位，彻底绕开。
- 跨域/跨层链接用 vault 相对路径：`[[丹房/00-思考与认知/含人量]]`、`[[原料/xxx]]`。
- 链接文本里的引号、特殊字符必须与目标文件名**逐字一致**（Obsidian 精确匹配），否则红链——尤其弯引号 `""` 与直引号 `""` 不能混用。

### 章节标题

- 用 `##` 作为一级子标题
- 数字编号用中文：`## 一、` `## 二、`，不是 `## 1.`
- 子节用 `###`，不编号，用描述性标题

### 块引用链接

当补角内容引用其他丹房页时，用：

```markdown
> 与[[目标页]]同构——解释关联逻辑
```

### 简洁骨架（首次创建自动生成）

新建页面自动生成简洁骨架：

```markdown
---
标题: 页面标题
创建日期: YYYY-MM-DD
更新日期: YYYY-MM-DD
品级: 下品
标签: [主标签, 子标签]
---

# 页面标题

#主标签 #子标签

[正文——AI 提供的完整 Markdown 内容]

## 推荐阅读

- [[相关页面一]] — 简述
- [[相关页面二]] — 简述

> 补角来源：[[原料/xxx.md]]
```

**注意**：首次创建不生成编译真理/时间线两区结构。两区由 `page_compress` 工具在页面有多次更新后按需引入。

### 推荐阅读

每页末尾必须有 `## 推荐阅读`，列出相关丹房页的 wikilink：

```markdown
## 推荐阅读

- [[页面一]] — 简述
- [[页面二]] — 简述
```

**质量约束**：
- 数量 3-15 个，去重
- **不同域优先**——优先链不同域页面，扩展知识图覆盖
- **不链自己**——不能把当前页放进自己的推荐阅读

### 原料来源

若页面从原料提炼，末尾注明：

```markdown
> 补角来源：[[原料/xxx.md]]
```

## 视觉规范（Obsidian 阅读视图体验）

页面不仅是数据——人在 Obsidian 里打开时要好读。以下语法在编辑视图看着是标记，阅读视图变成彩色区块。

### Callout（彩色侧边栏）

```markdown
> [!important] 核心结论
> 最重要的判断放在这里。全页仅一个。

> [!warning] 已知矛盾
> 标注已知矛盾/张力——"A 与 B 之间存在未闭合的冲突，此处列出双方依据"。

> [!tip] 关键洞察
> 值得注意但不至于是核心结论的观点。可用在对比之后、案例之后。

> [!note] 补充说明
> 背景信息、方法论补充、与现有框架的关系说明。

> [!question] 待解决问题
> 当前未闭合的问题、需要后续验证的假设。
```

**使用原则**：
- `> [!important]` — 核心结论。每条一个独立段落，放在章节末尾或核心论点后。一页 ≤3 个
- `> [!warning]` — 已知矛盾/张力（列出双方依据，不闭合）
- `> [!tip]` — 放在对比表格、案例分析之后
- `> [!note]` — 补充性内容，不打断主逻辑流
- `> [!question]` — 放在相关段落末尾，标记为"待验证"
- 不用 `> [!danger]`

### 高亮

```markdown
==关键术语== 在首次出现时高亮。一页 ≤5 处。
```

**使用原则**：
- 每次概念**首次出现**时高亮
- 一页不超过 5 处，密集高亮 = 没有高亮
- 表格内的术语不高亮（表格本身已够结构化）

### 隐藏注释（AI 元数据）

```markdown
%% 这是给 AI 看的，Obsidian 阅读视图不显示 %%
```

**适用场景**：
- 页面维护提示（如 `%% 待本页满 3 处内联引用后升级为上品 %%`）
- 暂存备忘（如 `%% TODO: 等待原料/xxx 的补充数据后更新第二节 %%`）

**禁止**：不要在 `%%` 里放用户隐私、敏感信息、大段原文。

## 原料模板

### frontmatter（YAML）

```yaml
---
# 元数据（必填）
标题: 原料标题
日期: YYYY-MM-DD
来源: IMA笔记·灵台开发 / 网页 / 微信读书 / 手动录入
类型: 洞察              # 原则/方法/案例/反模式/洞察/工具
置信度: 中              # 高/中/低
主题: [AI, 内容创作]     # YAML 数组，自由标签

# 提炼管线（系统自动维护，录入时可不填）
处理状态: 待提炼
处理日期:
提炼摘要:
回链:
---
```

### 字段说明

**录入时必填（5 字段）**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `标题` | ✅ | 原料描述性标题 |
| `日期` | ✅ | 原料创建/获取日期 |
| `来源` | ✅ | 渠道标识，便于追踪和过滤 |
| `类型` | ✅ | 知识形态分类 |
| `置信度` | ✅ | 信息可信度评估 |

**`类型` 枚举**：

| 值 | 含义 | 典型内容 | 提炼倾向 |
|----|------|---------|---------|
| `原则` | 通用规律、底层逻辑 | "AI不是更快的工具，是轨道级重构" | 建概念页 |
| `方法` | 操作步骤、SOP、流程 | "冷启动五步法" | 建方法页 |
| `案例` | 具体实例、实战复盘 | "某博主3个月从0到10万粉" | 补充到已有页 |
| `反模式` | 常见错误、避坑 | "AI写作去痕迹的五个误区" | 标注为警示 |
| `洞察` | 个人观察、直觉判断 | "我发现抖音算法最近在推长视频" | 待验证，可能降级 |
| `工具` | 软件/平台/产品参考 | "Obsidian Dataview 使用说明" | 建工具页 |

**`置信度` 枚举**：

| 值 | 含义 | 提炼策略 |
|----|------|---------|
| `高` | 多源交叉验证，或来自权威来源 | 直接提炼 |
| `中` | 单一来源但内容可靠 | 正常提炼 |
| `低` | 推测/直觉/未验证 | 标注待验证，不直接用于建新页 |

**系统自动维护字段**：`处理状态`、`处理日期`、`提炼摘要`、`跳过理由`、`回链`、`提炼目标`——由 `refine_mark` 和 `raw_preprocess` 自动写入，人工不直接编辑。

### 渐进式推进

- **新入库原料**：5 个必填字段齐全才进入提炼管线
- **已有原料**：提炼时顺手补标，不一次性批量修改
- `fetch_ima_notes.py` 抓取时自动填充 `标题`、`日期`、`来源`、`IMA笔记ID`，`类型` 和 `置信度` 留空待人工确认
