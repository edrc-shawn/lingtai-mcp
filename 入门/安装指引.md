# 灵台 MCP 安装指引

灵台 MCP 是一个本地知识管理服务端，所有 AI 桌面客户端共享同一套记忆和知识库。

---

## 第一步：确认前置条件

- 已克隆灵台仓库到本地
- Python 3.10+
- 至少一个支持 MCP 的 AI 桌面端

---

## 第二步：选择连接方式

### 方式 A：MCP 直连（推荐）

直接将灵台 MCP Server 注册到客户端的 MCP 配置文件中。

**配置示例**（以 WorkBuddy 为例，`~/.workbuddy/mcp.json`）：

```json
{
  "mcpServers": {
    "lingtai-kb": {
      "command": "python",
      "args": ["-m", "lingtai_kb.server"],
      "cwd": "/path/to/edrc/灵台/.tool/lingtai-kb",
      "env": {
        "LINGTAI_VAULT": "/path/to/edrc/灵台"
      }
    }
  }
}
```

其他客户端（Reasonix / Claude / Trae）配置方式类似，路径指向相同的 `.tool/lingtai-kb/`。

**验证**：新会话中说"调 context_load"，如果返回知识库统计信息则连接成功。

### 方式 B：Git 仓库同步

适用于不支持 MCP 的客户端或临时环境。

1. 确保客户端能读写灵台仓库目录
2. 客户端直接读取 `AGENTS.md` 获取执行规则
3. 通过 Git pull/push 同步其他客户端产生的内容

**限制**：记忆银行（`memories.json`）仅在 MCP 直连时可用。Git 同步模式下，AI 通过 `AGENTS.md` + Git 仓库文件获取上下文。

### 方式 C：兜底云记忆（仅 WorkBuddy）

如果以上两种方式都不可用，灵台在 WorkBuddy 上会降级使用 WB 云记忆作为上下文来源。但这只是过渡方案——云记忆由 WB 服务端自动总结，质量和时效性不如灵台 MCP。

---

## 第三步：首次启动（种子导入）

灵台 MCP 首次启动时，如果记忆库为空：

1. **自动检测**：扫描已知的客户端数据路径
2. **种子导入**：从 WB 云记忆（`~/.workbuddy/memory/xxx_memory.md`）解析已有用户画像和关键信息
3. **写入灵台**：导入内容写入记忆银行 + 画像三层
4. **接管**：之后所有客户端写入灵台 MCP，逐步积累自有记忆

**注意**：种子导入只做一次。之后新产生的记忆优先走灵台 MCP，WB 云记忆不再作为主源。

---

## 第四步：验证跨端同步

在客户端 A 对话中说"这是一条测试记忆"，然后在客户端 B 新会话中调 `context_load`，应能看到这条记忆。

如果跨端不生效：
- 检查是否连接了同一个灵台 MCP 实例（同一个路径、同一个端口）
- 检查 `LINGTAI_VAULT` 路径是否正确
- 检查 Python 版本是否 ≥ 3.10

---

## 常见问题

**Q: 多个客户端同时开启会冲突吗？**
不会。记忆写入是文件级操作，同一个服务端读写同一套数据文件，后写的覆盖。

**Q: 灵台 MCP 需要一直运行吗？**
不需要。MCP 是本地进程，客户端连接时自动启动，闲置自动退出。

**Q: 能在我另一台电脑上用吗？**
需要另一台电脑也克隆灵台仓库并安装 MCP。跨机器同步通过 Git。

**Q: 新电脑上装灵台，之前的对话记忆会丢吗？**
不会。记忆存在 `memories.json` 中（在 Git 仓库里），pull 后即可恢复。画像三层（`画像/`）同样在 Git 里。
