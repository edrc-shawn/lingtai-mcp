# 耳东怪诞正文配图

> 为公众号文章配图。AI 只负责出 shot list 和生图，不自己做确认。
> 所有确认节点由你（人类）完成——提高 Token 利用效率，不浪费算力在 AI 自审上。
>
> 方法论融合自小互 IP Studio + 小黑 Illustrations，角色和执行适配耳东。

## 不做什么

> 借鉴 dbskill 的边界定义方法：定义边界比定义功能更有用。

1. **不自己做确认** — AI 只出 shot list 和生图，所有确认节点由人类完成
2. **不画方框箭头叠加解释图** — 让角色做动作，不做PPT式标注
3. **不把耳东缩小到 <15% 画面占比** — 纸盒角色缩小后特征丢失，宁可少画一张
4. **不生成未经隐喻对照表验证的机制解释图** — 机制画错比没图更糟
5. **不做最终发布** — 用户确认后自行下到正文，AI 不碰发布环节

## 角色库

### 耳东（主角）
两个正方形纸盒子叠成的抽象手绘角色（上盒头+下盒下身），矩形黑色框眼镜（⚠️只在上盒出现一副，下盒绝不能有），纸盒质感，平静中性为基底根据文章情绪微调表情，认真做荒诞但成立的事。

完整规范：`erdong/erdong-ip.md`

### 倒倒（辅助角）
耳东的"反面"——身体塌陷/歪斜，不戴眼镜，演翻车、崩了、没电、自嘲的场景。
→ 完整规范见 `references/daodao-ip.md`

> 一篇只用 1 个主角色。耳东和倒倒不同时出场（除非画"期望vs现实"对比图）。

## 角色占比规则（必守）

| 图类型 | 耳东占比 |
|:------|:--------:|
| 解释图（流程/对比/结构） | 30-50% |
| 情绪图（状态/共鸣） | 40-60% |
| 四格漫画（故事/转折） | 每格30-50% |
| 封面图 | 80-100% |
| 信息图海报（总览） | 每格20-30% |

> 核心原则：**角色当主角来隐喻结构**。解释图不画方框箭头叠加——让角色做动作。
> ⛔ **海报中耳东不能走"极小嵌入"模式**——纸盒角色缩小后特征丢失，必须保持每格20-30%。

## 工作流（骨架）

### 1. 消化正文 + 认知锚点筛选
→ 见 `references/cognitive-anchors.md`

**1.1 选对点**：先过"三层分离+体裁制导"，锁定全文主张该画什么（防把支撑细节误当主图）。
**1.2 逐节筛选**：每节过三问过滤器，输出枚举表。判"配"的行继续。

### 2. 深层提炼
→ 见 `references/deep-reading.md`

**Q0 文体制导**：先定全文主张该画什么（防支撑细节抢主图位）。
**三问提炼**（真意/张力/灵魂话）+ Q4 必现内容清单。

### 3. 图类型分流 + 篇级判断
→ 见 `references/three-tracks.md` + `references/infographic-poster.md`

**3.1 三轨速判**：解释图/情绪图/四格漫画（逐锚点判）。

**3.2 篇级判断**（出shot list前过一次）：要不要配一张信息图海报？
- 命中任一 → 考虑配一张（且仅一张）总览海报：
  - ≥3步完整主流程 → 纵向编号流程海报
  - 一组并列对比/功能矩阵 → 横向分栏/网格海报
  - 需要一眼看全貌 → 开头放总览海报
- 不命中 → 照常走三轨散图

### 4. 隐喻发明 + 逐一对照 + 人小物大 + 一篇一世界 + 画外手势
→ 见 `references/metaphor-method.md`

**4.1 三步隐喻法** + 8种结构类型：抽象→物理→选物件→角色演它。

**4.2 隐喻逐一对照**（防"比歪"）：隐喻物件↔真实部件，写成对照表。
- 解释图：必须对照，机制画错比没图更糟
- 情绪图：可选对照，但核心隐喻仍需对得上
- 终判据：外行看完图+标注，能不能把隐喻"翻译"回真实机制？

**4.3 人小物大**（尺度戏剧）：被压/被困/够不到时，物极大+人适度小。
- 耳东占比：20-30%（不能<15%，纸盒特征会丢失）
- 物件占比：70-80%（大但留呼吸）
- 靠尺度不靠脸：情绪从"大小对比"出来，不是夸张表情

**4.4 一篇一世界**（可选，≥3张且同属一个机制域时启用）：整篇共用一个隐喻世界，每张图=世界里不同认知动作。
- 逃生口：某张图塞进世界会比歪 → 退出世界、单独现编

**4.5 画外手势**（可选构图装置）：画框外伸进手/工具，加"有人在场"现场感。
- 四种手势：递交/指向/遮噪/推动
- 不是每张都放，只在能干这四件事之一时出现

### 5. 出 shot list → 分布gate自检 → 确认

**单点图**（三轨散图）每张写清：主题/灵魂话/图类型/结构类型/必现内容/耳东动作/构图/占比/比例。

**篇级海报**（若步骤3.2判了起海报）：在shot list顶部单列一行——
- 主题/版式（纵向流程/横向对比/网格矩阵）/ 比例
- 每个panel：关键词 + 耳东动作 + 短标注（≤12字）

**分布gate自检**：出完shot list后过一遍——
- 情绪图占一半以上？→ 打回重判（除非全篇确实只需钩子）
- 有结构内容却画成情绪图？→ 换解释图
- 有时间线却用单张？→ 换四格
- 有海报+散图？→ 海报是地图，散图是景点，别重复

AI 只出 shot list，用户确认后才生图。

### 6. 生图前预检
→ 见 `references/anti-ppt-qa.md`（生图前部分）

### 7. 生图
→ 见 `references/prompt-template.md`

Agnes Image 2.1 Flash，传锚点图做 img2img。

> ⚠️ **必须用 Agnes API**（`https://apihub.agnes-ai.com/v1`，OpenAI 兼容，`.tool/config/api_keys.json` 的 `agnes`），**不可用 WorkBuddy 自带 ImageGen 工具**——后者不支持 img2img，会导致耳东角色从文字凭空生成、与锚点图漂移（曾因此返工）。调用脚本：**推荐 `作品/配图/png/layered-confirm-illustrations/gen_driver.py`**——manifest 驱动（读 shots.json）、强制 img2img 传锚点图、503/429 自动退避重试、有界并发、断点续跑，是流程顺畅的关键。`batch_gen.py` / `agnes_gen.py` 是纯文生图范例、**不传锚点图**，仅作接口演示，真实生图勿用（会角色漂移）。img2img 字段与锚点路径见 `references/prompt-template.md` + `存档/官方参考/内容处理/Agnes Image 2.1 Flash ✅已消化.md`。

### 8. 生图后 QA
→ 见 `references/anti-ppt-qa.md`（生图后部分）

### 9. 插入文章（编排脚本 run.py）

`prompts.md` 手工留档已砍掉——manifest(`shots.json`) 即真源，生图结果由 `gen_driver.py` 写的 `manifest_result.json` 记录，无需手抄。

端到端编排：**`作品/配图/png/layered-confirm-illustrations/run.py`** 把「确认 shot list 之后」到「插回文章」自动跑完：
- 读 `shots.json` → 调 `gen_driver.py` 生图（重试/并发/断点）→ 把**非封面图**以 `![[name.png]]` 插到文章 `<!-- shot:NAME -->` 占位标记 → **封面图**更新到 front matter 的 `cover` 字段（**不插入正文、不计入正文图数**）→ 输出报告。

用法：
```
cd 作品/配图/png/layered-confirm-illustrations
python run.py --article 文章.md
python run.py --article 文章.md --manifest shots.json --workers 3
python run.py --article 文章.md --dry-run     # 只打印插入计划，不动文件
python run.py --article 文章.md --force       # 全量重跑生图
```

约定：
- shot 标 `"cover": true` → 视为封面：进 front matter、不进正文、不计入正文图数。
- 占位标记 `<!-- shot:NAME -->`：NAME 匹配 shot 的 `name` 或其数字前缀（如 `01` 匹配 `01-two-extremes`）。
- 无占位标记的**正文图**自动追加到文末（带 sentinel 区块，重跑覆盖不重复）。
- 生图失败的图保留占位标记，`--force` 重跑补齐。

> 两道人工闸不变：确认 shot list 再生图（run.py 之前）、生图后 QA（run.py 之后，由你完成）。run.py 只接「确认完之后」的机械搬运。
