# 会话洞察自动沉淀

AI 从对话中提取四类信号，生成候选卡片，用户确认后入库。

## 触发方式

| 触发词 | 场景 | 行为 |
|-------|------|------|
| "总结到灵台" | 对话中途，提炼当前段 | 扫描本次对话+之前已产出，分批处理 |
| "结束" | 对话自然收尾 | 扫描整段对话全部产出，一次性归档，不留未处理候选 |

**快速通道**："结束"时，若本轮产出已全部 git commit（规则/日志/工作记忆均已落地），跳过候选卡片扫描，直接走机械收尾。避免重复提取已入库信号。

可多次"总结到灵台"，最终"结束"收尾。

## 提取信号

只提取以下四类信号，**其他忽略**（过程讨论、试错路径、重复解释不提纯）：

| 信号类型 | 判定依据 | 示例 |
|---------|---------|------|
| 决策/结论 | 明确了选择方向或原则 | "用provider抽象层起步，不从Pi的transformMessages开始" |
| 概念关联/修正 | 发现新关联或纠正旧认知 | "灵台定位是协作OS，非自主Agent" |
| 架构/设计洞察 | 涉及系统设计层面的见解 | "规划应预编码而非交给ReAct运行时" |
| 议题/待办 | 新发现的有价值方向 | "B方向值得做沉淀方案" |

## 产出：候选卡片

每张卡片按以下格式输出，用户逐条 ✓保留 / ✗丢弃 / ✎修改：

```
□ [融入既有页 / 新页 / 日志条目] 目标路径
  内容摘要（1-3句）
  操作说明
```

**卡片类型**：

| 类型 | 条件 | 目标 | 内容 |
|------|------|------|------|
| 融入既有页 | 已有目标页面且内容可追加 | 指定丹房页面 | 在哪个位置加什么内容 |
| 新页 | 全新概念，无合适既有页可融 | 丹房对应域 | 标题+frontmatter+1-3段正文 |
| 日志条目 | 操作记录性质 | 日志.md | 标准格式条目 |

**融入优先原则**（按顺序判定）：
1. 搜索是否存在语义匹配的既有页面
2. 存在 → 确定插入位置
3. 不存在 → 检查是否属于某个域的合理扩展
4. 都不行 → 才建新页

## 执行流程

用户全部确认后：

1. 写入/更新目标丹房页面（融入的追加，新建的创建）
2. **Obsidian 视觉语法合规检查**：新页或补充内容必须检查四项——
   - 核心结论 → `> [!important]`，关键洞察 → `> [!tip]`，补充说明 → `> [!note]`
   - 概念首次出现用 `==高亮==`（单页 ≤5 处）
   - 维护提示用 `%% 注释 %%` 嵌入
   - 正文 wikilink 用 `[[页|别名]]` 加显示文字，不让长链接读不通
3. 追加 `丹房/日志.md`，格式：`[YY-MM-DD HH:mm] 沉淀归档 | 摘要 | → 涉及页面`
4. git commit（scope 精准，只提交改动文件）

## 设计约束

- 触发靠自然语言，确认是勾选操作——不增加操作负担
- 知识能塞进既有页面就不建新页——融入优先
- 只沉淀提炼后的知识，不存对话原文——不冗余
- AI 只做候选，不做执行——必须经人确认
- 日志时间用系统时间，不硬编码
