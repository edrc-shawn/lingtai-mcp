# 灵台技能书写规范

> 对照来源：`技能/外部参考/awesome-claude-skills`（Anthropic 系官方 skill 集合）
> 配套文档：`技能/capability-map.md`（体系 B 源资产定位）/ `AGENTS.md` 规则⑰（端无关与能力协商）
> 适用范围：`技能/` 下所有文档式 skill（体系 B 源资产）

---

## 一、灵台技能的定位（为什么和官方不同）

| 维度 | 官方 awesome-claude-skills | 灵台 `技能/` 文档式 skill |
|------|---------------------------|--------------------------|
| 本质 | 给**任意 Claude 实例**的入门指南（可分发 zip） | 给**灵台协作者实例**的操作手册（体系 B 源资产） |
| 绑定 | 绑 Claude 实例 | 绑**灵台 MCP 契约**（规则编号 + 工具名），端无关 |
| 分发 | 打包 zip 跨端共享 | 留在 `技能/`，由 `gen_skill_index.py` 索引；强端按需派生体系 A（见 capability-map §四） |

**结论**：灵台 skill 不必、也不该改成通用格式——它的价值恰恰在于嵌死了灵台自己的规则和工具链。本规范只吸收官方的**工程纪律**，不碰灵台的**专用性**。

---

## 二、从官方吸收的 5 条工程纪律

### D1 · 路由 description（最重要）

官方把 `name` + `description` 当作 skill 的唯一路由信号，且 `description` **必须第三人称写清"何时用"**（"This skill should be used when..."）。

灵台对齐做法：
- 保留现有 `name` / `标题` / `trigger` 字段；
- **`description` 改写为第三人称触发句**，让未来的 AI 协作者能直接根据它判断是否触发。

```
反例（名词堆砌）：AI 与用户对话时的感知规则执行链——知识注入/信息保存/关联推荐/检索纪律
正例（触发句）：当用户提问/提供信息/新会话启动时，执行灵台感知规则链（知识注入·信息保存·关联推荐·三步检索）
```

### D2 · 渐进披露 · 单文件瘦身

官方规则：SKILL.md 主体 **< 5k 词**，只留核心流程；长参考材料拆到 `references/` 按需加载。

灵台对齐做法：
- 主文件只留**执行阶段表 / 工具链 / 质量门控 / 使用方式**四块骨架；
- 超过约 300 字、可独立查阅的参考材料（schema、API、长案例）拆到 `references/` 子目录，主文件仅留「路径 + 用途 + 何时读」。

### D3 · 资源三分（有代码/模板时遵守）

| 官方目录 | 灵台对应 | 装什么 |
|---------|---------|--------|
| `scripts/` | `脚本/` | 可重复执行、需确定性的代码（Python/Bash） |
| `references/` | `references/` | 按需加载进上下文的文档（schema/政策/API） |
| `assets/` | `资产/` | 输出产物用的文件（模板/图片/字体），不进上下文 |

当前灵台 skill 多为纯方法论文档，无强制分层；一旦包含代码或产出模板，按此三分。

### D4 · 写作对象与风格

- **对象**：写给「未来的灵台协作者 AI 实例」，不是只给当前会话看。假设读者已连接灵台 MCP、读过 AGENTS.md。
- **风格**：指令式中文（祈使句），给步骤不给闲聊；可参考但不用硬套官方的英文 verb-first 形式。

### D5 · 创建与校验

官方流程：`init_skill.py` → 编辑 → `package_skill.py`（自动校验）→ 迭代。

灵台对齐：
- 新建走本规范 §四 的 frontmatter 模板；
- 索引由 `gen_skill_index.py` 自动生成（已覆盖 配图/写作/视频/工程 目录）；
- 未来可补一个灵台版 `validate_skill.py`（校验 frontmatter 必填 + description 触发句格式），非当前必需。

---

## 三、灵台**保留**项（不改）

| 项 | 保留理由 |
|----|---------|
| 富 frontmatter（`标题`/`日期`/`skill_id`/`trigger`） | 中文工作流需要，比官方 name+description 更实用 |
| 嵌灵台规则编号（规则④①等）与工具名（`perception_save` 等） | 这是体系 B 源资产的契约，是灵台 skill 的核心价值 |
| 中文指令式写作 | 面向中文协作者，非英文 verb-first 强制 |
| 多文件并存于 `技能/` | 端无关，谁接灵台 MCP 谁消费，无需打包分发 |

---

## 四、推荐 frontmatter 模板（灵台版）

新建任何 `技能/` 文档式 skill 时，复制此头：

```
---
标题: <中文名>
日期: YYYY-MM-DD
skill_id: <snake_case>
name: <英文名/触发关键词>
description: <第三人称触发句：本技能用于……当……时应使用>
trigger: <触发时机短语>
---

# <中文名>

## 执行阶段
（阶段表：时机 / 核心规则）

## context_load（上下文加载）
（来源 / 优先级 / 触发时机）

## tool_chain（工具链）
（步骤 → 灵台 MCP 工具调用）

## quality_gate（质量门控）
（门控条件表）

## 使用方式
（典型用户指令 → 对应动作）
```

## 五、与体系 A 派生关系

- 本规范**只管体系 B 源资产**（文档式 skill）。
- 派生成体系 A 真 skill（如 WorkBuddy 的 `.workbuddy/skills/`）按 `capability-map.md` §四 映射表执行，**不改本文件、不取代文档式本体**。
- 派生规则：文档更新后，体系 A 真 skill 应重新派生。
