## 入口分流

| 入口 | 触发 | 处理方式 |
|:-----|:-----|:---------|
| 对话归档 | 用户明确触发 | 扫描整段对话产出，提取四类信号→候选卡片→用户确认→入库 |

## context_load（上下文加载）

| 来源 | 优先级 | 说明 |
|:-----|:-------|:-----|
| `原料/` | mandatory | 待提炼原料队列 |
| `丹房/索引.md` | mandatory | 已有知识域结构，判断归属域 |
| `丹房/` | mandatory | knowledge_search 搜索关联页，判断覆盖范围 |
| `入门/灵台用户画像.md` | optional | 了解用户风格偏好 |

## tool_chain（工具链）

```
手动提炼（原料→丹房）:
  1. 读料 → 判断原料特征（单域/多域）
  2. 单域 → 直接定位目标页 → 执行操作（建新页/补充/存原料）
  3. 多域 →
     a. 提炼关键要点（暂存上下文，作为 knowledge_search 的基础）
     b. knowledge_search 搜索关联页（涉及哪些域/概念/实体）
     c. 逐页执行操作：
        - 无合适页 → 建新页（初始中品）
        - 已有页缺此观点 → 补充（末尾追加 blockquote）
        - 已有页已覆盖 → 跳过本页
        - 内容矛盾 → ⚡递条（待工具）
  4. refine_mark（原料FM标记已提炼 + 写入提炼摘要 + 日志 + git commit）

对话归档（会话洞察自动沉淀.md 工作流）:
  1. 扫描对话产出，提取四类信号：
     ① 决策/结论
     ② 概念关联/修正
     ③ 架构/设计洞察
     ④ 议题/待办
  2. 生成候选卡片（三种类型）：
     ① 融入既有页面（补充）
     ② 新建丹房页面
     ③ 日志条目
  3. 用户逐条确认：✓保留 / ✗丢弃 / ✎修改
  4. 确认后执行：
     写入丹房页面 → 追加丹房/日志.md + oplog.jsonl
     → sys_refresh_index → git commit

```

## quality_gate（质量门控）

| 门控 | 条件 | 动作 |
|:-----|:-----|:-----|
| 提炼价值判断 | 跳过流程性/常识性内容 | 只保存具体知识 |
| 品级门控 | 下品≥单源 / 中品≥1交叉引用 / 上品≥3页面联引 | 不足则降级处理 |
| 用户确认 | 对话归档需用户逐条确认；上品页补充需确认 | ✓保留 / ✗丢弃 / ✎修改 |
| Obsidian 视觉语法 | 新页/补充必须检查四项（见规范细则） | 缺项则补上再入库 |
| 收尾流水线 | 每次写入后必做 | 日志+索引+git+记忆（§5） |

### Obsidian 视觉语法规范细则

引用 `入门/页面模板.md` §视觉规范，提炼入库前检查四项：

| 检查项 | 要求 | 违反处理 |
|:-------|:-----|:---------|
| Callout | 核心结论用 `> [!important]`，关键洞察 `> [!tip]`，补充说明 `> [!note]`，待解问题 `> [!question]`；一页 ≤3 个 `[!important]` | 追加或替换裸 `>` |
| 高亮 `==术语==` | 每次概念首次出现时高亮，一页 ≤5 处 | 补充或减少 |
| 隐藏注释 `%%...%%` | 维护提示（品级升级条件、待补充备忘）⚠️ 不放隐私 | 补充 |
| Wikilink 别名 | 正文中用 `[[页\|显示文字]]`，不让长链接读不通 | 加 `\|` 别名 |

## 使用方式

```
→ 提取四类信号 → 生成候选卡片 → 用户确认 → 入库

手动提炼（原料→丹房）:

→ 多域：提炼摘要 → knowledge_search搜关联页 → 逐页执行 → refine_mark
```
