# 自进化引擎安全护栏

## 设计意图（一句话内核）

> "AI 在夜里试错，人类在早晨拍板。不做自动生效。"

移植自微软 SkillOpt-Sleep（microsoft/SkillOpt）。把"把 skill 当神经网络参数训练"降维成**离线夜间自进化引擎**：定时收割行为数据 → 挖模式 → 回验 → 定级 → 暂存，**决定权留人**。

## 五阶段管线（骨架）

```
harvest → mine → replay → consolidate → stage → (human adopt)
```

- **harvest**：只读收割行为数据（会话转录 / 工具调用序列 / 纠正记录 / 观察）
- **mine**：从数据挖可复现模式 → 候选规则（带去重 + 续编）
- **replay**：在历史数据回验"若当时有此规则会怎样" → 正向率 / 风险率
- **consolidate**：按规则类型阈值定级（🟢 高 / 🟡 中 / ⚪ 低）
- **stage**：写入暂存区，**永不直接改活文件**

## 双泳道（正交，不冲突）

| 泳道 | 数据源 | 产物 | 信号特征 | 价值 |
|------|--------|------|---------|------|
| 模式泳道 | 工具调用会话 | 感知规则 / 配置 | 稀、泛化弱 | 学交互规律 |
| 教训泳道 | 纠正记录 | 记忆银行（lesson） | 稠、高频、具体 | 学"人" |

两条泳道数据源与产出去向都不同，可并行。教训泳道是真正资产（具体、人的、高频信号）；模式泳道需护栏防噪声。

## 不做什么

> 借鉴 dbskill 的边界定义方法：自进化引擎的风险是"做了不该做的事"，边界比功能重要。

1. **不自动生效** — 所有候选规则存入暂存区，人类拍板后才生效
2. **不直接改活文件** — 永不直接修改 AGENTS.md、SKILL.md、丹房页
3. **不覆盖人类纠正** — 已有人类纠正记录的方向，自动跳过不挖
4. **不在低置信度下自动合并** — 规则合并（merge）需 ≥0.7 置信度，否则只存不合并

## 三重安全护栏（核心：防无人值守固化错误）

### P0：连续 N 次 run 都出现才自动采纳

🟢 规则不首次即生效，需连续 `ADOPT_MIN_CONSECUTIVE`(=3) 次 run 都作为候选出现，才写入活文件；否则留 `staged/` 待人类 review。

- **消除的风险**：单次 harvest 异常（如某会话疯狂重复调用）不会把错误规则固化进活文件。
- **实现**：per-source 计数器存 `adoption_guard.json`；本次未以 🟢 出现的 source 计数归零（连续要求）；已采纳的从护栏移除（dedup 兜底）。

### P1：类型白名单

只有"有失败 / 缺口后果"的模式类型才走 P0 自动采纳：

```
AUTO_ADOPT_TYPES = {"dead_end", "knowledge_gap", "cooccurrence"}
```

纯频率类（`tool_sequence` 合并重复调用）即使拿 🟢，也**永远只进 `staged/` 待 review，不自动写入**。

- 信号质量排序：`knowledge_gap > dead_end > cooccurrence >> tool_sequence`
- 理由：合并类规则对单用户价值低，属"系统在记自己的操作日志"，不该无人值守固化。

### P2：留出集验证

按时间戳把会话切 **训练集(旧) / 留出集(新)**：**训练集挖模式，留出集回验**。候选不再在同份数据"挖了又验"。

```
_split_holdout(sessions, val_ratio=0.3):
    按 timestamp 升序 → 后 30% 为 val
    无时间戳 → 全归 train
    会话 <5 条 → 不切分，退回全量
```

- **效果**：旧版循环自证给 `kb_search→kb_search` 打 🟢(9/9)；留出集回验只匹配 1/8 → `positive_rate` 暴跌到 0.19，露出"只在老数据成立、不泛化到新会话"的自指本质。
- 零 API 成本（不重跑任务，只切分计数）。

## 自动采纳双门槛（最终姿态）

```
自动采纳 = 类型 ∈ AUTO_ADOPT_TYPES
          AND 连续 3 次 run 都出现为 🟢 候选
其余（含所有 tool_sequence🟢 与 🟡）→ staged/ 待人类晨间 review
```

## 去重机制（防重跑重复追加活文件）

- `_load_adopted_sources()`：读活文件「来源」行，提取已采纳规则的 source 集合
- `_max_rule_num()`：取「已采纳 + 已 staged」最大 R 编号，新规则**续编**（不从 R01 起步）
- `_is_valid()`：`pattern_id` 已在已采纳集合 → 跳过
- `pattern_id` 与「来源」行对齐（如 `deadend_kb_query`）；死胡同合并**去 `_merged` 后缀**，否则与「来源：deadend_X」对不上、去重失效

## 与原版 SkillOpt-Sleep 的差距（边界：别当完整移植）

| 维度 | 原版 | 灵台轻量版 |
|------|------|-----------|
| 回验 | LLM 重跑任务 + 留出集实测变好 | 启发式计数 + 频次/风险定级（已加 P2 切分但仍是计数） |
| 防震荡 | best_score 历史 + rejected-edit buffer | 无（靠 P0 连续出现兜底） |
| adopt | 独立步骤，人触发（除非显式开） | 🟢 内联即时（已加 P0/P1 约束） |
| 独有 | — | 教训泳道 + 记忆银行、去重、领域护栏 FORBIDDEN_PATTERNS |

**取舍合理**：单用户知识库每晚 LLM 重跑成本/收益不划算，但"用留出集验证是否真泛化"的精神用 P2 切分计数保留了。

## 常见坑（实测踩过）

1. **os.remove fail-closed**：沙箱把 `os.remove` 包成"回收站不可用时拒绝删除" → 自动采纳清理 staged 时抛异常 → 摘要谎报 `auto_adopted:0` 且出现"活文件 + staged 双重存在"。→ 清理改 best-effort(`try/except`)，写入成功即采纳，清理失败不回滚。
2. **正则匹配加粗「来源」行失效**：活文件那行是 `**来源**：`，正则 `来源[:：]` 因中间夹 `**` 匹配失败 → `adopted_sources` 恒空 → 去重形同虚设。→ 改为 `来源\**\s*[:：]`。
3. **rule_key 丢配对**：`tool_sequence` 候选 `rule_key` 只写单工具名（如 `kb_search`）丢了 `→` 配对 → replay 拿 `pair("kb_search→kb_search")` 比对 key 永远不成立 → 全误判 ⚪。→ 改带完整 `a→b`。

## 何时用 / 何时不该用

- **用**：agent 系统需"从自身行为学习并自动沉淀规则"，且有人周期性 review（晨间扫 staged/）。
- **不该用**：① 把 🟢 免审即时生效当默认（除非 P0 已加）；② 以为它是原版 benchmark 实测进化体（它是启发式轻量版）；③ 单会话数据 <5 条还指望留出集有效。
