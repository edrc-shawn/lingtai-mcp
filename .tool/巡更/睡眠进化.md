# 睡眠进化

> 所有操作通过灵台MCP 工具完成。人类在睡觉，不发消息。

## 步骤

### 第1步：状态感知

1. `mcp__lingtai-kb__knowledge_stats` — 知识库统计
2. 观察层无独立工具（旧 `observation_stats` 已下架）→ 用 `knowledge_stats` 的链接/孤立数 + `skillopt_dryrun`/`skillopt_run` 的 harvested 量替代
3. `mcp__lingtai-kb__skillopt_status` — 检查 staged 规则
4. `mcp__lingtai-kb__skillopt_log(days=1)` — 上次进化结果

pending 或 observations 不足时提前结束并登记日志。

### 第2步：Dry-run 预览

`mcp__lingtai-kb__skillopt_dryrun` 预览本轮预期产出。harvested=0 → 登记跳过后结束。

### 第3步：执行进化

`mcp__lingtai-kb__skillopt_run` 完整轮次（harvest→mine→replay→consolidate→stage）。

### 第4步：检查结果（摘要输出）

`mcp__lingtai-kb__skillopt_status` 查看 staged 规则分布：
- 🟢 自信度 ≥ 0.85：推荐采纳
- 🟡 自信度 ≥ 0.60：待晨间审阅
- ⚪ 自信度 < 0.60：继续观察

**Token 约束**：输出**数量分布**和**类型统计**即可——不逐条展开规则内容，不 dump 文件全文。具体规则留待晨间审阅时再看。

### 第4.5步：每日变化简报（晨间直送）

> 目的：把"昨天灵台发生了什么 + 夜间引擎做了什么 + 需要你拍板什么"三件事，用大白话+对比，怼到明早你眼前。本步产物是每轮最终报告的**首段强制内容**，且必须通过 present_files 交付。

**变化窗口**：运行日的上一个自然日 00:00–24:00（即"昨天一整天"）。睡眠进化 03:00 跑，总结昨天，符合"夜间总结昨天"。

0. **提取昨日动账（只读 git 元数据，允许用 `git log`，这是 git 读取、非脚本绕过 MCP）**：
   ```bash
   cd /c/Obsidian仓库/edrc/灵台
   SINCE="<运行日-1> 00:00"; UNTIL="<运行日> 00:00"
   git log --since="$SINCE" --until="$UNTIL" --format="%s"
   ```
   据此统计并挑 3-5 个最值得看的页（按主题去重，不列衍生重复）：
   - 新建/提炼页数、更新/补充页数、补链数、总提交数
   - 若运行环境无 `git`（自动化运行时），回退 MCP 指标对比：取 `knowledge_stats` 当前值 vs 昨日 baseline（存于简报末尾 `<!-- baseline -->` 隐藏段）算差值。

1. 汇总"待判断"项（取自第1-4步已取数据，必要时补取 `memory_search`(include_pending+include_archived 取其 stats 计数)/`knowledge_gaps`）。**本段做"相对每日检的增量"，不重复报绝对值**：
   - **基准提取**：读 `体检/日报/每日检摘要.md`（取最近一次，即前一日 18:00 产出），提取其报告的 `记忆银行 pending`（🟡关注或快照表「灵识主动打理·记忆银行 pending/active/archived」）与 `知识缺口`（若 🟡区/系统扫描有列）。grep 不到则记 `na`。
   - **🟡 候选**：`skillopt_status` 返回 `level=🟡` → 列 `rule_id`/置信度/类型/一句话 → **需老陈裁决**（每日检不覆盖此维度，照常列）
   - **⚪ 候选**：`level=⚪` → 列 `rule_id`/置信度 → 标注"继续观察，暂不需动作"
   - **记忆 pending（写差值）**：`今夜值` vs `每日检基准值`：
     - 格式 `pending {基准}→{今夜}（每日检 18:00 已自动归档 {基准-今夜} 条{若今夜仍>20：，今晨需抽检低置信度；否则：，已回归安全线无需你动}）`
     - 仅当 `今夜值 > 20` 才给抽检建议；`≤20` 写"无需动作"
   - **知识缺口（写增量）**：`今夜 {N} 条`；对比基准 `每日检列 M 条` → 写 `（每日检未单列 / 较每日检 +{N-M}）`；统一给"提炼 backlog，非紧急"建议

2. 写入 `体检/进化/睡眠进化/变化简报-YYYY-MM-DD.md`（人类可读），结构：
   - `# 灵台每日变化简报 YYYY-MM-DD`
   - `> 一句话结论（昨天灵台长了多少 + 夜间引擎是否需你拍板）`
   - `## 一、昨天灵台发生了什么（MM-DD）` → 新建/提炼N页（列主题页名）+ 更新M页 + 补链K条 + 总提交X次 + 一句话人话
   - `## 二、夜间引擎做了什么（睡眠进化 轮）` → 收割/模式/候选/采纳/教训/衰减，配人话 + 一句话
   - `## 三、待你判断（相对每日检的增量）` → 记忆银行写 `{基准}→{今夜}` 差值 + 知识缺口写增量，避免与每日检重复报绝对值
   - `## 四、给你的一句话行动建议`
   - 末尾隐藏段 `<!-- baseline: {pages,links,islands,obs_active,mem_pending,mem_active,mem_archived,gaps} -->`（供明日对比）

3. **最终报告首段必须是本简报**（标题 `## 📋 灵台每日变化`），不得被长报告淹没；并 `present_files` 该文件。

### 第5步：自动采纳

🟢 → `mcp__lingtai-kb__skillopt_adopt` 自动采纳。🟡 → 标注"待晨间审阅"不自动采纳（留待第4.5步清单待老陈裁决）。

### 第5.5步：记忆银行遗忘归档 + 灵识主动维护

1. 遗忘归档已内置进 `skillopt_run`（内部 `mem_decay` 自动跑：衰减+晋升+清理超时pending+连续低置信度自动归档）→ 无需独立调用。归档条数取 `skillopt_run` 返回的 decayed/deprecated 计数字段
2. `memory_search`(include_pending=true/false + include_archived=true) — 用其返回的 stats 计数得到 pending/active/archived 分布（旧 `memory_stats` 独立工具已下架），静默记录
3. **灵识主动维护 + 预筛（先过一遍再交人，不等人开口）**：
   - **预筛 pass（pending > 20 即触发，交人前必做）**：用 `memory_search`/`memory_consolidate` 对 pending 做一遍初审，产出**已消化清单**而非原始堆：
     - 明显够格（高置信 / 重复 / 过期候选）→ 直接 `mem_link` 毕业或 `memory_search` 定位后标弃，不占人时间
     - 明显可弃（连续低置信 / 重复噪声）→ 列「建议丢弃」清单，交人一键确认
     - 相关项聚类归组 → 人一次定夺一组
     - 目标：把 57 条原始堆压到 **5–10 条真悬停项**再交人终裁
   - pending > 动态红线 → 日志标注警告。动态红线 = `max(50, 近7日均值 × 1.5)`；近7日均值由 `memory_search` 按日 `created` 取计数近似（或读历史简报 baseline 段推算），**禁止再用固定 >50 静态判断**（繁忙周会天天误报），且**不跑 python 脚本**（违反本 spec 第123行「不跑 Python」）。本步结论以动态红线为准。
   - 检查知识缺口 → 如有新增严重缺口 → 日志标注
4. 阈值检查（防假阳性，严格按此执行）：
   - **取值**：只用 `skillopt_run` 返回的 `decayed`/`deprecated` 当轮增量（记为 `archived_round`）
   - **对比**：用 `memory_search`(include_archived=false, include_pending=false) 返回的 active 计数（当前活跃数）
   - **公式**：`archived_round > active × 0.3` → 触发「记忆衰减加速」
   - ❌ **禁止**用累计 archived 做对比（旧 `memory_stats.archived` 累计值几乎永远超标，只要历史归档超 8 条就天天触发），制造永久假阳性。
   - **示例**：`skillopt_run` 返回 `decayed=0`，`memory_search` active=16 → 用 `0 > 16×0.3=4.8`? 否 → **不触发**。若误用累计 archived 28 > 4.8 → 假阳性。
   - 触发时在日志摘要末尾追加 `| 记忆衰减加速: 当轮归档X >> 活跃Y×30%`

### 第6步：日志登记（人类版日志已退役，仅写 oplog.jsonl）

写入 `丹房/.meta/oplog.jsonl`（追加到末尾）：
```jsonl
{"t":"YYYY-MM-DDTHH:MM:00+08:00","op":"WB","mode":"auto","type":"skillopt","summary":"每日睡眠进化：收割X条→模式Y个→候选Z条→已采纳N条→遗忘归档A条","links":["sleep@0300"]}
```

### 第7步：Git 提交

只暂存本轮实际产出，避免污染历史（工作树常含无关的 lingtai-kb 开发改动）：
```bash
cd /c/Obsidian仓库/edrc/灵台
git add "体检/进化/睡眠进化/变化简报-YYYY-MM-DD.md" "丹房/.meta/oplog.jsonl"
# 若本轮回改了规程/脚本，追加对应文件，绝不 git add -A
git commit -m "skillopt: 每日睡眠进化 $(date +%d%H)"
```
**禁止 `git add -A`**（会裹入无关开发改动，污染历史）。

## 注意事项

- 所有步骤用 MCP 工具调用，不跑 Python 脚本
- 出错后记录错误，继续后续步骤
- 03:00-05:00 不发消息给人类
- 连续 3 天 harvest=0 时降低频率，日志标注"无新数据持续X天"
- **晨间直送（强制）**：第4.5步生成的待判断清单是每轮最终报告的**首段强制内容**，并通过 present_files 交付；这是"晨间查阅产物"，非 03:00 主动打扰消息。report 结构 = `## 🔔 今夜待你判断`（来自清单）→ 其余执行摘要。

## 自检

| 检查项 | 方法 | 异常动作 |
|:------|:-----|:---------|
| 无新数据 | harvest=0 提前结束 | 正常行为，连续 3 天→降低频率 |
| MCP 失败 | 工具调用返回值 | 记录错误，继续后续步骤 |
| 自动采纳 | 自信度 ≥ 0.85 的规则是否被采纳 | 未采纳→日志标注「自动采纳失败」 |
| 待判断清单 | 第4.5步是否生成 digest + 最终报告首段是否为其 | 未生成→补写并置顶报告；未 present_files→补调用 |
