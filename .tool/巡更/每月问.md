# 每月问

扫描页面时效（git log 驱动，不再依赖 `时效:` YAML 字段）+ 台律演化建议。

## 约束

- 不运行 lint（每日检已跑过）
- L1 仅限格式/事实类可确定错误
- 台律只建议不修改（须用户确认 + 正交审查）
- 改规则前先读 `体检/系统/灵识-skillopt状态.md#🧪-验证测试套件` 的问知用例，验证通过率

## 执行步骤

### 1. 扫描页面时效

```bash
python .tool/scripts/scan_expiry.py
```

- **原理**：对丹房每页取 `git log -1 --format=%ci` 最近提交日期，对比 90 天阈值
- **兜底**：git 无记录的新文件回退到 mtime
- 输出 JSON: expired（>90天无提交）+ still_valid + untracked

### 2. 筛选过期页面

从结果中找 `days_since_commit > 90` 的页面。

### 2.5 深度检测（每月一次）

以下步骤从每周查移入，频率适度：

#### 2.5.1 GBK 编码检查

```bash
cd /c/Obsidian仓库/edrc/灵台
python .tool/scripts/check_gbk_encoding.py --fix
```

有修复 → git add + commit + 日志。无输出跳过。

#### 2.5.2 死工具 + 工具覆盖报告

```bash
python .tool/scripts/dead_tool_check.py
python .tool/scripts/tool_coverage_report.py
```

输出死工具清单（30天零调用）和覆盖矩阵。有死工具 → 记入报告建议审查。

#### 2.5.3 语义扫描

```bash
cd /c/Obsidian仓库/edrc/灵台
"C:\Users\39029\.workbuddy\binaries\python\envs\semantic_temp\Scripts\python.exe" .tool/scripts/semantic_scan.py --threshold 0.75 --json
```

筛选涉及本月新增页的未链接对。

#### 2.5.4 自动语义链接

对每对页面: 读两页内容 → 找相关段落 → 添加内联 `[[链接]]` → 标记 ✅ → 写入对账。逐对 LLM 调用，token 成本高，每月跑一次足够。

#### 2.5.5 记忆管线维护

```bash
# 1. 查待毕业候选 → 确认后 memory_link 毕业
memory_consolidate(min_confidence=0.7)
# 2. 扫描记忆冲突
memory_scan_conflicts()
# 3. 遗忘归档（衰减+清理超时pending）
memory_decay()
```

### 3. 对话输出

列出过期候选清单:
| 页面 | 创建日期 | 距今天数 | 建议 |
|:----|:-------:|:-------:|:----|
| ... | ... | ... | 已过期/仍有效 |

深度检测结果:
- GBK 编码修复: N 篇
- 死工具: N 个（建议审查）
- 语义扫描命中: N 对
- 自动语义链接: N 条
- 记忆管线: 毕业 N / 归档 N / 冲突 N

### 4. 台律演化建议

数据来源:
1. 当月日志: `grep -o '"t":"2026-07' 丹房/.meta/oplog.jsonl | wc -l` 或 `grep '"type":"提炼"\|"type":"修复"\|"type":"重构"' 丹房/.meta/oplog.jsonl` — 提炼异常/分流困难/框架变更频率
2. 对账推迟项: `体检/系统/对账.md` ⏳ 条目 — **同一项≥2次未修 → 自动升级⚠️规则盲区，排入本段输出最前两条**
3. 上品待议积压: ≥3条未审阅 → 保护过严；全被手动融入 → 过松
4. 矛盾/挑战: grep `⚡矛盾` `⚡挑战` 密集区 → 分流表需细化
5. skillopt 健康度: 调用 `skillopt_status` 查看 staged 数量。连续 3 轮收割 0 模式 → 检查 SessionTracker 数据源

输出:
```
## 台律演化建议（YYYY-MM）

| # | 建议 | 依据 | 影响范围 |
|:-:|:-----|:-----|:---------|
| 1 | ... | ... | ... |

无建议 → "本月台律运行平稳，无修订建议。"
```

用户逐条接受/拒绝。接受的按台律§七执行（变更摘要 + 正交审查 + 日志 + 提交）。

### 5. 记录

追加一行到 `丹房/日志.md`（人类版）+ `丹房/.meta/oplog.jsonl`（机读版）。

```bash
git add -A && git commit -m "review: 每月问——时效核查 + 台律演化建议"
```

## 自检

| 检查项 | 方法 | 异常动作 |
|:------|:-----|:---------|
| 时效扫描 | scan_expiry.py 输出中包含 expired 页 | expired>0 才对过期页逐一处理 |
| 对账延项 | ⚠️升级项排在台律建议最前两条 | 漏排→日志标注「对账延项优先级未遵守」 |
| 台律建议 | 至少输出「无修订建议」 | 无输出→日志标注「台律演化建议段缺失」 |
| 用户确认 | 对话输出必须有用户决策入口 | — |
