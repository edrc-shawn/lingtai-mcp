# 巡更·自愈管线（7 步闭环）

> 借鉴 llmwiki 的 self-healing 7 步，把灵台巡更 L1（自动修）/ L2（只扫不修）升级为系统化闭环。
> 对应知识库范式对比报告的启示 ③。编排脚本：`self_heal.py`。

## 设计原则

- **L1 自动修**：低风险、可逆项，脚本直接修复（如缺 `标题` frontmatter）。
- **L2 只扫不修**：中/高风险项（如弯引号文件名——改名会断双链），只报告不自动改，交人工。
- **闭环可追溯**：每轮产出自愈报告（体检/日报/自愈报告/）+ 归档日志（self_heal_log.jsonl）。

## 七步

| 步 | 名称 | 动作 | 产出 |
|----|------|------|------|
| 1 | 检测 | 扫描丹房：缺标题 FM、弯引号/直引号文件名等 | findings 列表 |
| 2 | 分类 | 按风险分 L1（可自动修）/ L2（只报不修） | l1 / l2 |
| 3 | 修复 | 仅对 L1 应用安全修复（补 `标题`） | fixed 列表 |
| 4 | 复查 | 重新检测，确认 L1 已清零 | recheck findings |
| 5 | 报告 | 写 `体检/日报/自愈报告/{ts}.md`（FM日期格式 YYYY-MM-DD HH:MM） | 报告文件 |
| 6 | 归档 | 追加 `self_heal_log.jsonl`（ts/总数/已修/剩余） | 日志 |
| 7 | 回写索引 | 跑 `build_index.py` 刷新内存索引 | 索引更新 |

## 运行

```bash
# 默认 dry-run：检测/分类/报告/归档，但不改文件、不刷索引
python .tool/巡更/self_heal.py

# 实际应用 L1 修复并回写索引
python .tool/巡更/self_heal.py --apply
```

## 与现有巡更的关系

- `每日检.md` / `每周查.md`：人工/自动化跑的巡检 runbook，产出体检报告。
- `self_heal.py`：把其中「发现→修」环节固化为可重跑的闭环，补上 llmwiki 式「检测→修复→复查→报告」的系统性。
- 建议挂到每日检自动化末尾，作为收尾自愈步骤。
