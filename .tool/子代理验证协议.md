# 子代理验证协议

高置信度场景下，将声明分解为原子命题，由独立子代理逐条验证——子代理之间天然信息隔离，看不到原始上下文，打破自我确认偏差。这与 Vibe Coding 方法论中的**对抗式审查**同构：多 Agent 并发从不同架构假设出发，找出单线程思维覆盖不到的盲区。^[补角：第一性原理→拆框架回到事实，对抗式审查→攻击自己的框架假设——两者合起来构成"生成-验证"闭环。[[原料/从_第一性原理_到_对抗式审查__读懂 Vibe Codin.md]]]

## 原理

来自 MARCH 框架的核心发现：**检查者不应看到原始输出。** 当验证者先看到完整答案时，会倾向于"为原文找合理性"而非独立判断——这是"LLM-as-Judge"范式的固有缺陷（自我确认偏差）。

子代理验证协议通过**会话级隔离**实现信息不对称：每个子代理独立启动，只收到一条原子命题，不知道命题来自什么上下文、是谁生成的。这不是技术层面的隔离（调的都是同一个灵识），而是**认知层面的隔离**——子代理不知道彼此的存在。

## 触发条件

- 用户显式要求验证（"这个靠谱吗""你确认一下"）
- 系统输出涉及**上品知识**或**高置信度声明**
- 用户对某个结论提出质疑
- 输出中包含可能引发争议的事实性主张（数字、引用、归因）

日常闲聊、纯观点表达、明显正确的常识不需要触发。

## 协议流程

### 第一步：声明分解

调用 `analyze_text` + 定制 prompt，将目标声明拆解为独立的原子命题。

```
输入：一段声明文本（如"缝隙策略与predictive coding的prediction error在结构上同构"）
输出：["命题1：缝隙策略是判断力生长的必要条件",
       "命题2：predictive coding中prediction error是学习信号",
       "命题3：两者共享同一认知结构"]
```

分解原则：
- **最多3条命题**。超出3条说明分解粒度过细，检查是否有命题在同一维度上重叠
- **命题之间必须彼此独立**：一条命题的验证不依赖另一条命题的结果。如果命题B需要"如果命题A成立则..."，说明B不是独立命题，应合并或删除
- **每个命题应是可独立验证的事实性主张**（不是观点，不是元评论）
- **每个命题一句话**（过长则继续拆分）
- 分解步骤本身有 API 成本和幻觉风险——分解错了后面全歪。必要时人工复核分解结果

### 第二步：启子代理逐条验证

为每个原子命题启动一个独立子代理。**子代理的prompt必须明确告诉它可以调用灵识 search/query 检索灵台知识库**（不能默认它自己会想到去用，否则它可能只做公开搜索，漏掉灵台内部专有概念）。

```
子代理A  ← 收到"命题1"（看不到原文、看不到其他命题）
  → 独立调用灵识 search/query 验证
  → 返回：✅支持 / ⚠️部分支持 / ❌无证据 + 证据摘要

子代理B  ← 收到"命题2"
  → 同上

子代理C  ← 收到"命题3"
  → 同上
```

子代理之间**互不知晓**。每个子代理只看到一条孤立命题，必须靠自己的检索判断真伪。

### 第三步：汇总验证报告

```
验证报告

命题1：缝隙策略是判断力生长的必要条件
  ✅ 支持（灵库3条证据：判断力页/福柯补角/制度困境）
  
命题2：predictive coding中prediction error是学习信号
  ❌ 无证据（灵库未收录predictive coding概念）
  
命题3：两者共享同一认知结构
  ⚠️ 部分支持（缝隙页的三重映射支持，但缺少外部神经科学佐证）

整体置信度：中等（2/3命题有证据覆盖，但核心外部概念缺位）
知识缺口：predictive coding/预测编码——灵库无覆盖
```

## 与共识协议的关系

| | 共识协议 | 验证协议 |
|---|---|---|
| 目的 | 预防错误——多通道交叉确认 | 检测错误——独立审查已有结论 |
| 方向 | 从问题到答案（检索强化） | 从结论到证据（验证强化） |
| 机制 | 三通道独立检索 | 子代理信息隔离 |
| 时机 | 回答问题时 | 回答之后/用户质疑时 |

两者可以串联使用：
1. 共识协议 → 输出带置信度的答案
2. 用户质疑某结论 → 验证协议 → 对该结论做独立审查

## 限制

- 子代理有会话级开销（多次agent启动），不适合高频场景
- 分解步骤依赖 LLM（调用 analyze_text，有 API 成本），分解质量直接影响验证效果
- 子代理验证的结果仍然受灵识知识库覆盖范围限制——灵库没有的东西，子代理也查不到
- 验证报告的质量取决于命题分解的粒度：粒度过粗（一个大命题）≈没验证，粒度过细（语气词都拆）≈浪费
